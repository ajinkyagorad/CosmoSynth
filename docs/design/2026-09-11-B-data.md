# CosmoSynth 2.0.0 design, Section B: the data plan

*Design document, 2026-09-11. Section B of the 2.0.0 design set, in
`~/projects/CosmoSynth/docs/design/`. It changes no code; the implementers work from this text.*

**Authority.** The binding decisions 1 to 9 from the orchestrator, `CLAUDE.md`, and the eight research
reports in `docs/research/2026-09-11-*.md`. This document refers to the research reports by slug, for
example `[data-beyond]` for `2026-09-11-data-beyond-and-cmb.md`, and likewise `[mw-atlas]`,
`[solar]`, `[fiction]`, `[arch]`, `[quest-render]`, `[render-audit]` and `[build]`.

**Evidence tags.** **VERIFIED** means that either a research report measured it on 2026-09-11 (it
cites that report) or I measured it for this document on 2026-09-11 with read-only probes from
triton (it says "probe"). **INFERRED** means reasoning, literature from memory, or an untested
assumption. An implementer must confirm every INFERRED item before relying on it. §9 lists them all.

**What this section owns.** What every shipped data file contains, where it comes from, its licence,
its byte layout, the importer that makes it, the engine-free Core type that reads it, and the tests
that prove it is the real sky. **What it does not own.** Rendering, including how a layer draws,
shaders, LOD and the distance-compression formula (Section A, Foundation, and the render sections
own those). UI. The code structure of `Runtime/` beyond the loading contract in §3.

**Six findings the implementers must not rediscover:**

1. **AT-HYG's magnitudes are not Johnson V for bright stars** (probe). In `hyglike_from_athyg_v40`,
   118,237 of 119,670 rows have `mag_src = T` (Tycho). **Sirius is −1.088 there, against −1.44
   in HYG v4.4**; Arcturus is +0.16 against −0.05, and Betelgeuse 0.77 against 0.45. B−V is blank
   for Sirius, Arcturus and Vega. The existing known-answer test (Sirius −1.44) would fail on a
   naive drop-in. The fix is cheap and exact: **every one of the 119,614 hyglike rows that carries a
   `hyg` id matches HYG v4.4 `id` one-to-one, and their `hip` values agree** (probe). So the importer
   takes astrometry from AT-HYG and photometry from HYG v4.4. That keeps the brief's
   "drop-in hyglike" for everything it is good at.
2. **AT-HYG positions are epoch J2000.0** (probe). Barnard's Star has Dec 4.69328°, against the J2000
   value 4.6934° and the J2016 value 4.7395°. AT-HYG also carries velocities (`vx, vy, vz` in pc/yr;
   Barnard's comes to 142 km/s, which matches the 142.5 km/s computed from its proper motion,
   parallax and RV), so stars can move under the deep-time warp.
3. **The Planck column lies about its units** [data-beyond]. `I_STOKES_INP` is in µK although its
   TUNIT says K_CMB. Every FITS bake asserts a physical range and never trusts TUNIT.
4. **The two CF4 grid families use opposite axis orders** [data-beyond]. The watershed labels are
   x-fastest; the 64³ δ grid is z-fastest. Its box geometry was verified by fit, and the paper's
   text disagrees with it.
5. **ESA archive data is CC BY-NC 3.0 IGO, not CC BY-SA** [data-beyond]. This covers Planck, Gaia and
   Hipparcos. `docs/data-sources.md` line 177 is wrong; §6 rewrites it.
6. **SBDB has exactly the belt populations we want** (probe): 32,294 asteroids with H < 14, 7,287
   TNOs, 1,047 centaurs and 16,391 Jupiter trojans. The query API as probed returns about four
   significant figures (Ceres `a = 2.766`), so the importer must request full precision and assert
   that it got it (§2.4).

## 1. Conventions shared by every dataset

### 1.1 One container for every new binary

Today there are two binary layouts: `CSS1` (a 16-byte header plus row records) and `CSM1` (meshes).
Ten new datasets would mean ten more hand-offset parsers. Instead, every new binary, the rebuilt
stars included, uses **one column-store container**. Each dataset keeps its own 4-byte magic, so a
file loaded under the wrong name is refused. `.csmesh` is out of scope and stays as it is.

```
CosmoSynth data container (all integers little-endian)
offset size  field
0      4     magic        4 ASCII bytes naming the kind, e.g. "CSS2" (table below)
4      4     version u32  layout version of that kind; the parser refuses any value it does not know
8      4     rows u32     rows of the primary table (for a grid: number of voxels)
12     4     flags u32    reserved, must be 0
16     4     metaBytes u32  length of the UTF-8 JSON meta block; a multiple of 8, padded with 0x20
20     4     reserved u32 must be 0
24     8     payloadBytes u64  bytes of column data after the meta block
32     metaBytes            meta JSON (§1.2)
32+metaBytes payloadBytes   columns, each starting at an 8-byte-aligned offset from the payload start
```

- **File length must equal `32 + metaBytes + payloadBytes` exactly.** A truncated download or a
  file written by another version is refused, exactly as `StarCatalog.Parse` refuses today.
- **Column types:** `u8 i8 u16 i16 u32 i32 f32 f64`. There is no `f16`: `System.Half` is not in
  netstandard 2.1, and the byte savings do not justify a hand-written converter.
- **Strings never live in columns.** Names are arrays in the meta JSON (at most 4,769 of them, for
  the exoplanet hosts).
- **Multi-table files:** a column may declare its own `"rows"` and `"table"` (for example `hosts`
  and `planets` in one exoplanet file). The header `rows` is the primary table.

| Magic | File | Kind |
|---|---|---|
| `CSS2` | `sky/stars.csstars` | stars |
| `CSEX` | `catalog/exoplanets.csexo` | exoplanet hosts + planets |
| `CSSB` | `sun/smallbodies.cssb` | osculating elements |
| `CSSA` | `sun/activity.cssa` | monthly solar indices |
| `CSDU` | `galaxy/dust.csdu` | voxel grid |
| `CSGP` | `galaxy/cepheids.csgp`, `globulars.csgp`, `masers.csgp` | point set (meta `kind` distinguishes) |
| `CSLV` | `lv/localvolume.cslv` | galaxy set |
| `CSRS` | `lss/2mrs.csrs` | galaxy set |
| `CSPT` | `lss/cf4_groups.cspt`, `lss/sdss.cspt` | point set |
| `CSGR` | `lss/cf4_basins.csgr`, `lss/cf4_delta.csgr` | voxel grid |
| `CSCB` | `cmb/cmb_sky.cscb` | cube-map sky |

`version` is 1 for every kind. The stars file's predecessor was the separate magic `CSS1`, which the
new parser refuses by name.

### 1.2 The meta block

The meta block is JSON, parsed in Core by the existing `Json.cs`. These keys are **required**; the
parser refuses a file that lacks one:

```json
{
  "kind": "stars", "schema": 1,
  "generator": "tools/cosmodata/build_starfield.py", "generatorCommit": "cf93a25+dirty",
  "generatedUtc": "2026-09-12T10:00:00Z", "licenceProfile": "sideload-nc",
  "frame": "ICRF", "epoch": "J2000.0",
  "sources": [ {"id": "athyg", "name": "AT-HYG v4.0 hyglike subset",
                "url": "https://codeberg.org/astronexus/athyg/media/branch/main/data/subsets/hyglike_from_athyg_v40.csv.gz",
                "retrievedUtc": "2026-09-12T09:58:11Z", "licence": "CC BY-SA 4.0", "licenceTag": "by-sa",
                "attribution": "…exact text from §6…"} ],
  "columns": [ {"name": "pos", "type": "f32", "components": 3, "unit": "pc", "offset": 0},
               {"name": "vmag", "type": "f32", "unit": "mag", "offset": 1436032} ],
  "provenance": { "pos":  {"class": "Measured", "source": "athyg", "reference": "…"},
                  "vmag": {"class": "Measured", "source": "hyg44"} },
  "provenanceBits": [ {"bit": 1, "field": "teff", "class": "Inferred",
                       "note": "spectral class only; no B-V published"} ],
  "provenanceCodes": [ {"bits": [8, 10], "field": "pos",
                        "values": {"1": {"class": "Measured", "note": "Gaia DR3 parallax"},
                                   "3": {"class": "Measured", "note": "Hipparcos 2007 parallax"}}} ],
  "uncertainty": {"pos": "dist_err_pc"},
  "counts": {"rows": 119669, "distanceUnknown": 146},
  "assertions": [ {"name": "sirius_vmag", "expected": -1.44, "tolerance": 0.05, "got": -1.44, "ok": true} ]
}
```

- **Grids** add a `"grid"` object with these keys:
  - `dims [nx,ny,nz]`, with x fastest in memory;
  - `sampling`: `"nodes"` (values at `origin + i·step`) or `"cells"` (value covers
    `[origin + i·step, origin + (i+1)·step)`);
  - `origin`, `step` and `unit`;
  - `frame`: `galactic-helio` | `supergalactic` | `ICRF`.
- **Quantised columns** carry an `"encoding"`:
  - `{"kind":"linear","scale":s,"offset":o}` decodes as `value = raw·s + o`;
  - `{"kind":"log8","lo":lo,"hi":hi}` decodes as `0 → 0`, and `v ≥ 1 → lo·(hi/lo)^((v−1)/254)`.
- **`provenanceBits` / `provenanceCodes`** turn a row's `flags` column into per-row, per-field
  provenance without shipping strings per row. **`uncertainty`** names the column that fills
  `FieldProvenance.Uncertainty`.
- **`assertions`** records every range and known-answer check the importer ran, with the value it
  got. An importer that fails an assertion writes nothing (§1.4). The record exists so a reader of
  the shipped file can see what was checked.

### 1.3 The code that reads and writes it

- **Python writer, `tools/cosmodata/csdata.py`** (new, stdlib).
  - `write(path, magic, meta, columns)`, where `columns` is a list of
    `(name, type, components, bytes, extra)`.
  - It aligns each column and fills `offset`, `columns` and `payloadBytes`.
  - It writes `path + ".tmp"`, flushes and `fsync`s it, then reads it back through its own reader:
    it checks the magic, the exact length, and the first and last element of every column.
  - Only then does it `os.replace`. On any failure it deletes both the temporary file and the stale
    target and exits non-zero. That is the `build_spacecraft.py` lesson, applied once instead of
    in every script.
  - `csdata.py --selftest` writes `tests/CosmoSynth.Core.Tests/fixtures/csdata_fixture.csd`: three
    rows, one column of each type, an encoding, a grid block and a bit override. This small
    committed file is the cross-language contract.
- **Core reader, `Core/Data/CsData.cs`** (new, engine-free).
  - API: `static CsData Parse(byte[] data, string expectedMagic, uint maxVersion)`, `JsonValue Meta`,
    `int Rows`, `bool Has(string column)`, `float[] F32(string)`, `double[] F64(string)`,
    `byte[] U8(string)`, `ushort[] U16(string)`, `uint[] U32(string)`, `int[] I32(string)`,
    `FieldProvenance ProvenanceFor(string field, uint rowFlags, int row)` and
    `string Attribution()`.
  - It copies with `Buffer.BlockCopy`, and asserts `BitConverter.IsLittleEndian` (true on arm64 and
    x64).
  - Every refusal is a `FormatException` whose message names the kind and the importer to re-run,
    following `StarCatalog`'s existing wording.
- **Core test, `CsDataTests`.**
  - It parses the committed Python-written fixture and checks every value.
  - Refusals: wrong magic; version too new; header and length disagree; a column running past the
    end; a misaligned offset; an unknown type; `metaBytes` not a multiple of 8; invalid JSON; a
    missing required meta key.
  - It also checks the round trip of `log8` and `linear` decoding at `raw = 0, 1, 255`.

Every dataset in §2 is a thin typed wrapper over `CsData`. It validates the columns it needs and
exposes typed accessors; the known-answer tests live in its own test class.

### 1.4 Importer rules (all `tools/cosmodata/*.py`)

1. **Standard library only.** The one existing exception is `npx` for Draco in
   `build_spacecraft.py`. This plan adds exactly one more, and `CLAUDE.md` must list it: **numpy**
   (system, 2.5.1, VERIFIED present) in `build_dust.py`, `build_cmb.py` and the grid part of
   `build_lss.py`, only for FITS cubes and HEALPix (binding decision 6). Nothing else may import
   numpy.

   The phenomena texts are converted from the user's `catalog.js` **once**, by hand, into an
   authored JSON (§2.15). The pipeline itself never runs node.
2. **Shared helpers, so no importer re-implements them:**
   - `fetch.py`:
     - `get(url, expect=...)` sniffs the magic bytes: gzip `1f 8b`; FITS `SIMPLE  =`; JSON `{` or `[`;
       a CSV whose header starts with an expected column name; zip `PK`;
     - `get_range(url, a, b)`;
     - three retries with backoff, a `CosmoSynth/2.0 (importer)` User-Agent, and timeouts.

     A 200 response is not evidence of data (the `build_starfield.py` rule).
   - `fits.py`, stdlib: `read_header(stream)` (the 2880-byte cards from `cmb_bake.py`),
     `image_layout(cards)` and `bintable_layout(cards)`. It returns offsets and dtypes; the numpy
     scripts wrap them.
   - `licence.py` (§1.5) and `csdata.py` (§1.3).
3. **Write to a temporary name, then `os.replace`, or write nothing.** On refusal, delete the stale
   target, so that "an artefact on disk is not evidence of the run" holds by construction.
4. **Physical range assertions on values, never on metadata.** Never trust FITS `TUNIT` or `BUNIT`,
   and never trust a column name. Each dataset's assertion list is in §2. A row that fails a
   per-row bound is dropped and **counted in `counts`**. A dataset whose drop count exceeds its
   stated budget is refused whole.
5. **Every run records** its sources (URL, retrieval time, licence tag), the generator commit
   (`git rev-parse --short HEAD` plus `+dirty`), and its assertions.
6. **Pin what can be pinned.** Use release tags or commit SHAs in raw URLs where the host supports
   them: LVDB `v1.1.1`, and the Stellarium commit resolved through the GitHub API. Record the
   resolved SHA.
7. **Run on triton only, niced.** Stream large inputs, and never keep them: the Planck FITS,
   Vergely's 40 MB cube (downloaded to `/tmp`, deleted on exit) and the CF4 zip member (a range
   fetch). Peak disk use is under 50 MB, which fits the 9 GB of free space (VERIFIED `df`).

### 1.5 The licence switch

`tools/cosmodata/licence.py` defines `PROFILE`, read from the environment variable
`COSMODATA_LICENCE`. The default is `sideload-nc`. Each source in each importer declares one
licence tag.

| Tag | Meaning | `sideload-nc` | `public-nc` | `commercial` |
|---|---|---|---|---|
| `pd` | US government / public domain | ship | ship | ship |
| `pd-ack` | public, acknowledgement required | ship | ship | ship |
| `cc0` | CC0 | ship | ship | ship |
| `by` | CC BY | ship | ship | ship |
| `by-sa` | CC BY-SA; the derived file is BY-SA | ship | ship | ship |
| `nc` | non-commercial (ESA CC BY-NC IGO, AAS via VizieR, A&A "scientific use", SILSO) | ship | ship | **fallback or drop** |
| `unclear` | no redistribution grant (Skowron, CF4 grids) | ship | **drop** | **drop** |
| `own` | the user's own work | ship | ship | ship |

- **Drop means the importer writes nothing and deletes the shipped file.** The ledger then omits it
  from `manifest.json`. The runtime loads only what the manifest lists (§3), so **dropping a source
  changes no code.**
- **Where a fallback exists, the importer writes the fallback to the same path and filename.** That
  is WMAP for Planck, Edenhofer for Vergely, SDSS-only for 2MRS, and the hand-entered giants for
  UNGC.
- **Stars are the exception.** The by-sa files carry ESA-derived astrometry, and whether that makes
  them `nc` is a lawyer question [data-beyond §2]. Under `commercial`, `build_starfield.py`
  **refuses to run** until `tools/cosmodata/licence_decisions.json` records a decision. It must not
  silently ship, and it must not silently gut the sky.
- `ledger.py --check` fails the build gate (G0 in [build]) when any file in `StreamingAssets` is
  absent from the manifest, a manifest file is missing, or a file's `licenceTag` is not allowed by
  the recorded profile.

### 1.6 Frames and units (data side of binding decision 4)

- **Every position column is ICRF** (J2000 equator and equinox, epoch stated in meta), in the unit
  named by the column: pc for stars and Milky Way points, kpc for the Local Volume, Mpc for the LSS.
- **Grids are the one exception.** They are stored in their native frame (`galactic-helio` or
  `supergalactic`), because resampling them into ICRF would blur them. The grid meta declares the
  frame, and Core supplies the fixed rotations:
  - `StandardFrames.EquatorialToGalactic` exists today. Add a test that it equals the Hipparcos
    matrix below to 1e-9, since its 10-decimal print rounds at 5e-11:
    ```
    [[-0.0548755604, -0.8734370902, -0.4838350155],
     [ 0.4941094279, -0.4448296300,  0.7469822445],
     [-0.8676661490, -0.1980763734,  0.4559837762]]
    ```
    It has been checked against all 44,599 2MRS pairs: median 1.08″ [data-beyond §9.1].
  - Add `StandardFrames.GalacticToSupergalactic`. Its rows are SGX, SGY and SGZ in Galactic
    coordinates:
    ```
    [[-0.7357425748,  0.6772612964,  0.0         ],
     [-0.0745537784, -0.0809914713,  0.9939225904],
     [ 0.6731453021,  0.7312711658,  0.1100812622]]
    ```
    It has been checked against 55,877 CF4 pairs: median 0.17″ [data-beyond §9.2].
- **No file contains a Unity axis.** The ICRF→Unity mapping lives only in `FloatingOrigin` (binding
  decision 4). The CMB cube-map faces are defined in ICRF components (§2.13) for the same reason.
- **Units:** km and s inside Core bodies (unchanged), and the stated unit per column in the
  containers. Core converts at the boundary with `Constants.Parsec`, `KiloParsec` and `MegaParsec`.

### 1.7 The distance-scale convention (one H0)

- **All redshift-derived distances use H0 = 74.6 km/s/Mpc, with Ωm = 0.3153 in a flat ΛCDM
  comoving distance.** This is Cosmicflows-4's calibration (VERIFIED, CF4 ReadMe: "H_0_=74.6"). With
  it, 2MRS, SDSS and the named clusters land on the same radial scale as the CF4 groups, the CF4
  grids and the Dupuy & Courtois basins.
  - Using Planck's 67.4 for the redshift layers would put every cluster **10.7% farther out in the
    redshift layers than in the CF4 layers**: the Hubble tension, visible as a doubled structure.
  - The shape of the expansion history (Ωm) comes from Planck 2018 (VERIFIED 0.3153); only the
    distance scale comes from CF4.
- **Redshifts are converted to the CMB frame first:**
  `cz_cmb = cz_helio + 369.82 km/s · (n̂ · d̂_dipole)`, with d̂ from (l, b) = (264.021°, 48.253°). CF4
  already works in V_cmb. The conversion is first order in β (β = 1.2e-3), which is exact enough.
- **Then** `D_C(z) = (c/H0) ∫₀^z dz′/√(Ωm(1+z′)³ + 1 − Ωm)`. The importers integrate it in Python;
  `Core/Scale/Cosmology.cs` has the same function, and the tests compare the two.
  Known answers, VERIFIED by probe integration: **D_C(0.05) = 198.54 Mpc, D_C(0.1) = 392.20 Mpc,
  D_C(0.2) = 764.64 Mpc** (cz/H0 would give 200.93, 401.87 and 803.73).
- **CF4 h-scaled grids convert with h = 0.746** (Mpc = (Mpc/h)/0.746).
- **Planck's own numbers are quoted as Planck numbers.** These are not recomputed with 74.6:
  - χ* = 13.87 Gpc, the comoving distance to last scattering (4.28e26 m);
  - the age, 13.797 Gyr;
  - H0 = 67.36, for statements about the early universe only.

  At the CMB's radius, a 10% scale choice is invisible against 300 Mpc of galaxies (45× smaller).
  The CMB panel says "Planck 2018 ΛCDM".
- **Provenance of every redshift distance:** `Inferred`, source "Hubble-law comoving distance, CMB
  frame, H0 = 74.6, Ωm = 0.3153; peculiar velocities ±~1000 km/s (±13 Mpc) not removed".

### 2.1 Stars: AT-HYG astrometry + HYG v4.4 photometry (`sky/stars.csstars`, `CSS2`)

**Sources.** Both are by astronexus (D. Nash) under CC BY-SA 4.0.

| id | URL | What we take |
|---|---|---|
| `athyg` | `https://codeberg.org/astronexus/athyg/media/branch/main/data/subsets/hyglike_from_athyg_v40.csv.gz` (14,096,722 B, 119,670 rows, VERIFIED) | `x,y,z` (pc, ICRF, epoch J2000.0: probe, Barnard), `dist`, `dist_src`, `vx,vy,vz` (pc/yr), `rv`, `hip`, `hyg`, `proper`, `con`, `bf` |
| `hyg44` | `https://codeberg.org/astronexus/hyg/media/branch/main/data/hyg/CURRENT/hyg_v44.csv.gz` (13,636,362 B, 119,614 rows, VERIFIED) | `mag` (V), `ci` (B−V), `spect`, joined on `hyg44.id == athyg.hyg` |

**Join rule (probe, VERIFIED).**

- **The 119,614 matched rows (1:1) take `mag`, `ci` and `spect` from HYG v4.4.** Every matched
  row's `hip` agrees, and matched rows lose nothing: naked-eye counts stay exactly as shipped today
  (5,070 at V ≤ 6.0 and 8,920 at V ≤ 6.5, Sol excluded).
- **The 56 AT-HYG-only rows keep AT-HYG's `mag` and are flagged.** HYG v4.4's `mag` is Johnson V
  from Hipparcos, Yale BSC and Gliese. AT-HYG's is Tycho-derived and wrong for bright stars:
  - |Δ| has median 0.076 mag, p99 0.64 and maximum 4.6;
  - 3,830 rows differ by more than 0.3 mag, all of them `mag_src = T`;
  - Sirius is −1.088 against −1.44.
- **Sol (row 0) is excluded**, as today.

**Records.** 119,669 rows (plus up to ~100 from the optional census below), sorted by `vmag`

### 2.6 Core code instead of data: the Moon, deep-time planets, and reference tables

These are engine-free C# files with published coefficients. There is no importer; the tests are
the gate.

**`Core/Orbits/LunarTheory.cs`**: Meeus, *Astronomical Algorithms* (2nd ed.) chapter 47, the
truncated ELP-2000/82 of Chapront-Touzé & Chapront (1983).

- **Inputs:** TDB. The mean elements L′, D, M, M′ and F are cubic and quartic polynomials in T.
- **Series:** the eccentricity factor E, the additive terms A1–A3, Table 47.A (60 terms: Σl, Σr)
  and Table 47.B (60 terms: Σb). These give geocentric λ, β and Δ referred to the **mean ecliptic
  and equinox of date**.
- **Then** precess to J2000 (IAU 1976 Lieske angles, Meeus ch. 21 rigorous method), and convert
  ecliptic → ICRF with `StandardFrames.EclipticToEquatorial(ObliquityJ2000Iau1976Rad)`.
- **Do not add nutation.** The validation fixture is geometric J2000.
- **This fixes [solar §4.1]'s finding** that the same series, used without precession, is off by
  2,762 km (median).
- **It replaces the two-body Moon everywhere.** Earth = EMB − Moon_geo · GM_Moon/(GM_Earth + GM_Moon).
- **Tests (`LunarTheoryTests`)** use the 26 geocentric Moon vectors 2026–2031 in
  `fixtures/horizons_validation.json`:
  - **median error ≤ 20 km and maximum ≤ 50 km**. Meeus states ~10″ in λ and 4″ in β for this
    truncation, and 10″ at 384,400 km is 18.6 km; the maximum allows 2.5× for the distance series.
    If the measured error is larger, find the cause (equinox of date versus J2000 is the usual
    one) before touching the bound, per `CLAUDE.md`;
  - the Earth–EMB offset is |Moon| × 0.0121505 exactly, 4,670.6 km at 384,400 km.

  The coefficient tables are transcribed from the book (INFERRED: 120 rows to type). A transcription
  typo will show up as a periodic residual in this test.

**`Core/Orbits/StandishElements.cs`**: JPL "Approximate Positions of the Planets"
(<https://ssd.jpl.nasa.gov/planets/approx_pos.html>, VERIFIED reachable).

- **Table 1** (1800–2050) is already transcribed in [solar A.1], and its Mercury–Neptune values
  match JPL's page (VERIFIED [mw-atlas §4.11]).
- **Tables 2a and 2b** (3000 BC – AD 3000) must be transcribed from the same page. They include the
  b, c, s and f terms for Jupiter to Pluto:
  `M = L − ϖ + bT² + c·cos(fT) + s·sin(fT)`.
- **Evaluation:** [solar A.1], with ε = `ObliquityJ2000Iau1976Rad`.
- **Use:**
  - Pluto always comes from Table 2a/2b. JPL's current Table 1 has no Pluto row (INFERRED
    [mw-atlas B26]).
  - The eight planets use it whenever |t − 2026.0| exceeds the fitted conic's validated window
    (proposed: outside 2016–2036, with a one-year linear blend at the edges).
- **Tests (`StandishTests`):**
  - heliocentric direction error against the fixture ≤ 0.08° for all eight planets over 2026–2031.
    The measured worst case was 0.074° for Saturn [solar §4.1], so this bound is the measurement
    plus 8%;
  - Table 2 against Table 1 at J2000, within JPL's published Table 2 error;
  - **a new fixture vector: Jupiter at 1979-03-05 (Voyager 1)**, added by
    `fetch_validation_fixture.py`. The error must be within JPL's published Table 1 error for
    Jupiter (the value must be read off the same page: INFERRED magnitude).

**Build rules:**

1. **Every LVDB dwarf.**
   - `distance` (kpc) comes from the file. The importer asserts it equals
     `10^(distance_modulus/5 + 1)/1000` to 0.5%.
   - `ell`, `pa`, `rhalf_physical` and `M_V` are **taken as given, and a blank stays blank**, with
     its bit set. This is the Atlas's worst defect reversed: its 542/911 default ellipticities
     were drawn as if measured.
   - `M_V` blank but `apparent_magnitude_v` present → `M_V = m − DM`, provenance Inferred, bit set.
2. **UNGC rows not already in LVDB.**
   - Matching: angular separation < 2′ and |Δd|/d < 0.3, **or** a normalised-name match
     ("MESSIER031" ↔ "M31", "NGC0253" ↔ "NGC 253").
   - Of the unmatched rows, keep those with **M_K = Kmag − 5 log₁₀(Dist·10⁵) ≤ −19.5**, plus
     any row named in `overrides.json`. This yields the giants: M31, M33, M81, M82, NGC 253,
     NGC 5128, M83, IC 342, M101, NGC 4945, Maffei 1/2 and so on. The expected count is 40–80
     (INFERRED; the importer prints the list).
   - Size = the Holmberg radius (a26/2 × d), size kind "Holmberg" (not half-light). Axis ratio from
     UNGC `b/a`. T-type from `TT`.
   - The Milky Way row is kept but flagged `IsHome`, and is never drawn as a point. Its disc comes
     from `GalaxyModel`.
3. **PA for non-LVDB galaxies:** from `xsc` `Spa`, the nearest 2MASX within 30″ of the UNGC
   position. Otherwise the PA is unknown (bit set).
4. **Overrides win** and are Measured and cited. The file lists M31 (i = 77°, PA = 38°:
   Corbelli+2010, INFERRED values), M33 (i ≈ 55°, PA ≈ 22.5°: Corbelli+2014, INFERRED), LMC and
   SMC disc parameters (van der Marel & Kallivayalil 2014, INFERRED), and M81 and NGC 253 if the
   author finds kinematic values. `build_authored.py` also validates this file's references.
5. **Fallback** (profile `commercial`, or UNGC unreachable): the giants come from
   `giants_fallback.json` instead.
   - It has ~20 rows (MW, M31, M33, M81, M82, NGC 253, NGC 5128, M83, IC 342, M101, NGC 4945,
     Maffei 1, Maffei 2, NGC 55, NGC 300, M94, NGC 4258, M51, NGC 6946 and M104), each with RA,
     Dec, distance, D25 or a26, b/a, PA and T-type, and **one reference per value**.
   - These are facts transcribed from papers, released CC0 by the project.
   - When UNGC is available, the importer cross-checks the fallback against it (Δd < 15%,
     Δposition < 1′), so the hand file cannot rot unnoticed.

D3D. Every term is in **ICRF components**, so the file never contains a Unity axis.

| Face | Major axis | sc | tc | Texel direction from (u, v) = (2s − 1, 2t − 1) |
|---|---|---|---|---|
| 0 | +x | −z | −y | ( 1, −v, −u) |
| 1 | −x | +z | −y | (−1, −v,  u) |
| 2 | +y | +x | +z | ( u,  1,  v) |
| 3 | −y | +x | −z | ( u, −1, −v) |
| 4 | +z | +x | −y | ( u, −v,  1) |
| 5 | −z | −x | −y | (−u, −v, −1) |

- Texel (i, j) has its centre at s = (i + 0.5)/F, t = (j + 0.5)/F.

INFERRED: that Unity's `Cubemap.SetPixelData(bytes, 0, (CubemapFace)f)` puts row 0 at t = 0 on
Vulkan. **The runtime must prove this, not assume it.** The render section owns an editor or
harness check that samples the uploaded cube map *through the GPU* along the six face-centre
directions and the Cold Spot, and compares the result with `CmbSky.Sample`. If a face comes out
flipped, the fix is a flip at upload. **The data never changes.**

2. **Refuse unless** the rms is in (30, 300) µK (TUNIT is not trusted), |mean| < 10 µK, p1 and p99
   are within ±400 µK, and there are 0 NaN after the degrade (the inpainted column).
3. For every cube texel, take the ICRF direction from the table above, rotate it to Galactic with
   the Hipparcos matrix, and look up `ang2pix_nest(1024, z, φ)` (nearest).
4. Quantise, write the mask (degrade 2048 → 256 with the maximum over children of "is inpainted",
   then sample per texel), and write through `csdata`.
5. **Frame self-check before writing** (`check_frame.py`, VERIFIED on the equirect): the rms by |b|
   band decreases monotonically from |b| < 2° to |b| > 30°, and the **Cold Spot mean within 5° of
   (l, b) = (209°, −57°) is −112 ± 5 µK** (WMAP: −107 ± 6).

  good to one texel, which is all tap-to-measure needs);

- `TemperatureK(dir, CmbFrame frame) = T₀ + D_frame·(n̂·d̂) + ΔT(n̂)/10⁶`, with the constants from

    shipped.

  need them without running importers. Rebake at most once per release.
